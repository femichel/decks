Definición

La línea de comandos permite automatizar y repetir tareas administrativas de forma auditable — algo que la interfaz gráfica no ofrece a escala.

Windows Server Core (sin GUI) es cada vez más común en producción precisamente por eso: menor superficie de ataque y administración 100% scriptable vía PowerShell.

Ejemplo resuelto

Script de respaldo simple

PowerShell — respaldo automatizado
# Crear carpeta de respaldo con fecha
PS> $fecha = Get-Date -Format "yyyy-MM-dd"
PS> New-Item -ItemType Directory -Path "D:\Backups\$fecha"

# Copiar el sitio web a la carpeta de respaldo
PS> Copy-Item -Path "C:\inetpub\wwwroot\*" -Destination "D:\Backups\$fecha" -Recurse

# Eliminar respaldos con más de 30 días
PS> Get-ChildItem "D:\Backups" | Where-Object { $_.CreationTime -lt (Get-Date).AddDays(-30) } | Remove-Item -Recurse

Respaldo D:\Backups\2026-08-24 creado correctamente.

2.4.2 Aplicaciones y roles

Instalar roles y features por comando

PowerShell — gestión de roles
# Listar roles y features disponibles
PS> Get-WindowsFeature

# Instalar el rol de servidor web (IIS)
PS> Install-WindowsFeature -Name Web-Server -IncludeManagementTools

# Instalar un paquete de terceros con el gestor winget
PS> winget install --id Git.Git -e

Success. Web-Server instalado y en ejecución.

Caso de estudio

Cuando el script es más confiable que el clic

Buena práctica

En un despliegue de 15 servidores idénticos, un administrador configuró manualmente 14 y automatizó el último con un script PowerShell.

El servidor configurado a mano fue el único con una regla de firewall faltante — el error humano se repite de forma inconsistente; el script se equivoca, si acaso, de forma idéntica y detectable.

Conclusión práctica: documentar comandos como script, no solo como pasos de manual, reduce configuraciones divergentes entre servidores gemelos.

Glosario de comandos de administración

Individual30 min · Entregable: glosario documentado
  1. Investiga 15 comandos de PowerShell usados en la administración diaria del SO instalado.
  2. Para cada uno documenta: sintaxis, propósito y un ejemplo de uso real.
  3. Organiza el glosario por categoría: archivos, red, roles/features, usuarios.
  4. Prueba al menos 5 comandos en tu VM y adjunta la salida obtenida.
Criterios: exactitud de la sintaxis (40%) · ejemplos probados y funcionales (35%) · organización del glosario (25%).

Autoevaluación

Comprueba lo aprendido

¿Qué comando de PowerShell lista el contenido de un directorio?
Get-ChildItem (equivalente a dir en CMD).
¿Qué comando instala un rol de servidor como IIS?
Install-WindowsFeature -Name Web-Server.
¿Por qué preferir scripts sobre configuración manual en despliegues múltiples?
Porque reducen configuraciones divergentes entre servidores y hacen el proceso auditable y repetible.
2.4
TSO
Cierre

En cinco ideas

  • La CLI permite automatizar y auditar tareas que la GUI no puede escalar.
  • PowerShell reemplaza casi todos los comandos clásicos de CMD con verbos consistentes (Get-, Set-, Remove-).
  • Instalar roles y features por comando es reproducible entre servidores.
  • Un script mal escrito falla de forma consistente; un humano falla de forma impredecible.
  • Documentar comandos como glosario acelera la curva de aprendizaje del equipo.
