Definición

La interoperabilidad es la capacidad de sistemas operativos distintos para intercambiar y usar información de forma efectiva, mediante protocolos y formatos compatibles.

En la práctica de infraestructura real, casi ningún entorno es homogéneo: Windows para escritorio corporativo, Linux para servidores web y bases de datos — deben convivir e intercambiar datos todos los días.

Cliente NFS → N:
  • El cliente integrado de Windows admite NFSv2/v3; NFSv4.1 corresponde a su rol servidor.
  • Exportación de lectura limitada a la IP del Windows del equipo; no usar *(rw).
  • Comprobar versión y servicios antes del montaje. TCP 2049 por sí solo no basta para NFSv3.
  • La guía usa acceso anónimo y nolock para lectura; no evalúa bloqueo concurrente.

4.1.2 IPC entre sistemas

Sockets vs. RPC

Sockets
  • Comunicación de bajo nivel sobre TCP/UDP.
  • Independiente del lenguaje y el SO en ambos extremos.
  • El programador maneja el protocolo del mensaje manualmente.
RPC
  • Abstrae la llamada remota como si fuera una función local.
  • Necesita un contrato compartido; algunos sistemas, como gRPC, usan una IDL.
  • Ejemplos modernos: gRPC, XML-RPC, JSON-RPC.

4.1.2 · Ejemplo ejecutable

TCP transporta bytes; definimos mensajes

  • Solicitud: una línea UTF-8 terminada en \n. Una respuesta JSON, también terminada en \n.
  • El servidor lee hasta el terminador, responde y cierra esa conexión. Después acepta otra.
  • Timeout de 5 segundos y longitud máxima: evitar esperas indefinidas o mensajes sin límite.
  • El cliente recibe e imprime la respuesta. Un solo recv(1024) no garantiza un mensaje completo.

Caso de estudio

Un entorno mixto en producción

Infraestructura híbrida

Una empresa mantiene Active Directory en Windows Server para autenticación corporativa, mientras sus servidores de aplicaciones corren en Linux.

SSSD permite integrar el inicio de sesión Linux con Active Directory. Para un servidor Samba miembro de dominio en la familia RHEL se utiliza Winbind; no se debe asumir que configurar SSSD integra también las cuentas de Samba.

En estos laboratorios usamos cuentas locales de Samba. La unión a AD requiere una práctica específica y queda fuera de la evaluación.

Reto · Validar una entrega por dos vías

  • 30 min · Windows deposita entrega.txt por SMB como docente.
  • Rocky ejecuta el servicio con --carpeta /srv/samba/tso, con permisos de lectura y sin root.
  • Windows consulta ARCHIVO entrega.txt por TCP y compara bytes y SHA-256 con Get-FileHash.
  • P6: valores coincidentes; archivos inexistentes y rutas externas reciben ok: false.
  • Resolver una falla asignada y explicar individualmente cómo se encontró.

Cierre del curso

En cinco ideas

  • La interoperabilidad es el estado normal de la infraestructura empresarial, no una excepción.
  • NFS y SMB/Samba resuelven el intercambio de archivos entre Linux y Windows.
  • Sockets dan control de bajo nivel; RPC abstrae la comunicación como llamadas locales.
  • Permisos, identidad y diagnóstico determinan si el intercambio es correcto.
  • Una prueba positiva y una negativa demuestran más que una captura aislada.
